## 1. Что это за продукт

**Quant** (в коде и старых документах — QuantFlow) — **автоматический торговый оператор для Московской биржи**. Система читает свечи MOEX, оценивает их по заранее записанным правилам, измеряет накопленную «уверенность» в стратегии по закрытым сделкам, проверяет риск-лимиты **до** обращения к брокеру и исполняет заявку через Т-Инвестиции.

**Ключевое позиционирование:** проверяемость решения вместо обещаний доходности. На маркетинговом сайте **нет ни одной цифры результата** — ни win rate, ни profit factor, ни доходности. Это построенная позиция, а не пробел, и она подкреплена кодом: все конкретные технические заявления сайта проверены построчно и **подтверждаются** ([02 §6](02_REPOSITORY_AND_SYSTEM_ARCHITECTURE_AUDIT.md#6-торговое-ядро-и-aiml-соответствие-заявлениям-verified)).

**Что важно понять сразу:** это **однопользовательская система**, а сайт продаёт её как SaaS с подписками. В коде нет ни клиентских аккаунтов, ни подписок, ни платежей — единственная сущность человека — это «оператор» установки. Подробнее — раздел 8.

## 3. Основные пользовательские сценарии

**Что фактически может оператор с доступом:**
- Войти в Dashboard по логину/паролю; запустить или остановить торговый движок.
- Смотреть портфель, позиции, сделки, кривую капитала, просадку, сигналы, стратегии, гипотезы, риск-лимиты, события и audit trail — 12 экранов.
- Закрыть позицию и исполнить сигнал — с идемпотентностью, обязательной причиной и записью в журнал.
- Запустить бэктест и выгрузить результат; запустить цикл пересчёта статистики.
- Управлять системными учётными данными (значения не раскрываются в API).
- Торговать вручную из Telegram — двухшаговое подтверждение с проверкой подмены callback-данных.
- Получать уведомления о сделках, ошибках брокера и срабатывании риск-лимитов.
- Вести paper-торговлю с учётом комиссии и проскальзывания.

**Чего не может никто:** зарегистрироваться, оплатить, подключить свой брокерский счёт, подтвердить **автоматическую** сделку, получить поддержку, прочитать privacy policy, восстановить данные из бэкапа, узнать о сбое без ручной проверки.

## 8. Главное ограничение, которое нужно знать всем

**Система однопользовательская. Сайт продаёт подписки.**

Доказательства (все проверены):
- `grep -rniE "tenant|subscription|billing|stripe"` по `bot/` → **0** совпадений на 187 файлов.
- Ни одна доменная таблица не имеет `owner_id`.
- Один глобальный брокерский счёт: `TINKOFF_ACCOUNT_ID`.
- Telegram-доступ — статический whitelist `chat_id` из `.env`.
- Единственный способ создать пользователя: `python -m qf_platform.migrate --create-user NAME --role administrator`.
- Сайт публикует цены: Sandbox бесплатно / Live **5 000 ₽/мес** / Premium **10 000 ₽/мес**.

Сайт это **честно раскрывает** (`faq.a10`: «сейчас оплата вообще не подключена»), но только в десятом из десяти вопросов FAQ.

**Практический вывод:** не начинайте работу над клиентским кабинетом, подписками или онбордингом до решения [OQ-ARCH-01](14_OPEN_QUESTIONS_AND_DECISIONS.md) — это работа по неизвестному ТЗ.

## 13. Известные ограничения (кратко)

**Блокирует запуск:**
1. Нет клиентских аккаунтов, подписок, платежей ([A-01], [B-05]).
2. Автономный цикл торгует **без подтверждения человека**, хотя сайт обещает обратное ([A-02], [T-01], [P-03]).
3. Нет privacy policy, terms, раскрытия рисков — при собираемом email и активной аналитике ([S-01]).
4. Заявки на доступ по умолчанию **не сохраняются** ([W-01]).
5. Нет CI/CD; два гейта красные незамеченными ([Q-01]).
6. Нет бэкапа торговой истории и audit trail ([B-06]).
7. Нет мониторинга и алертинга ([Q-06]).
8. Dashboard только на Werkzeug dev-сервере ([D-02]).
9. `robots.txt`/`sitemap.xml` отдают placeholder-домен ([W-02]).
10. Audit trail неполон: не покрывает 2 из 3 путей исполнения сделки ([S-05]).

**Технический долг:**
- Торговое окно в наивном локальном времени, лог заявляет UTC ([A-04]).
- Два Telegram-бота; уникальная функциональность в legacy ([A-05]).
- Дубли: `bot/auth/` vs `bot/security/`, `/api/v1` vs `/api/v2`, две схемы БД, два `rules.yaml` ([A-06], [B-04]).
- ~12 000 строк торговой логики без тестов ([Q-05]).
- Решение не воспроизводимо: версия правил не сохраняется ([B-03]).
- 3 high-severity CVE в npm-дереве ([S-03]).

**Сильные стороны (не ломать):**

## 16. Как «уверенность» вычисляется на самом деле

Это самый часто искажаемый в документации механизм, поэтому вынесен отдельно.

```python
# bot/learning/belief_updater.py:305
new_confidence = current + (target - current) * CONFIDENCE_LEARNING_RATE   # 0.15
# затем :311
value = max(MIN_CONFIDENCE, min(MAX_CONFIDENCE, value))                    # [0.05, 0.95]
```

`target` рассчитывается из win_rate, profit_factor и expectancy по **закрытым** сделкам; статистика не считается достоверной до `MIN_TRADES_FOR_CONFIDENCE = 20`. Сигнал со стратегией ниже `MIN_STRATEGY_CONFIDENCE = 0.20` фиксируется в `skipped_signals`, но не исполняется.

Это **экспоненциальное сглаживание**. Ни машинного обучения, ни байесовского вывода. Сайт (`faq.a1`) описывает это точно; `README.md` — нет.

**Важная оговорка:** статистика агрегируется по `strategy_id` и **смешивает** сделки, принятые по разным версиям `rules.yaml` ([B-03](06_BACKEND_DATA_AND_INTEGRATIONS_AUDIT.md#b-03)). Поэтому её нельзя интерпретировать как характеристику текущей конфигурации правил.
