## 3. VirtualBox: установлен, не используется, но активен в сетевом стеке

| факт | значение |
|---|---|
| версия / установлен | **Oracle VirtualBox 7.2.10**, **2026-06-24** |
| виртуальных машин | **ни одной** (`VBoxManage list vms` пуст) |
| файлы `.vbox` / `.vdi` | не найдено ни одного |
| служба `VBoxSDS` | `Stopped`, запуск `Manual` |
| драйвер `VBoxNetLwf` | **Running**, тип запуска **System** |
| привязан и включён на адаптерах | **5 из 5**: `Ethernet`, `vEthernet (WSL)`, `vEthernet (Default Switch)`, `Ethernet 2`, `Ethernet 3` |
| `VirtualBox Host-Only Ethernet Adapter` | `Up` |

`VBoxNetLwf` — lightweight filter, встроенный в стек каждого адаптера, включая
`vEthernet (WSL)`, через который работает Docker. При каждой загрузке пишет в
System по две ошибки «internal driver error».

Гипотеза, что это **одна причина двух проблем** (`0x9F` при засыпании и
медленная публикация порта Docker после сна, §10б), записана как **Г3** в
`docs/PROJECT_STATE_PENDING_2026-08-02.md`, раздел 6. **Не проверялась.**

> **Оговорка о чистоте замера.** Команда `VBoxManage list vms` подняла два
> процесса — `VBoxSVC` и `VBoxSDS` (20:54). Это штатное поведение COM-сервера,
> настроек не меняет, на боевой контур не влияет. Записано потому, что
> «read-only» здесь оказался read-only не полностью.
