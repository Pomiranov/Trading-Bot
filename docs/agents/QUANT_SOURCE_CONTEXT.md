## 2. Что нужно знать до первой задачи

**Система однопользовательская, сайт продаёт подписки.** В `bot/` ноль совпадений на `tenant|subscription|billing|stripe`, ни одной таблицы с `owner_id`, один брокерский счёт, Telegram-доступ — статический whitelist. Сайт публикует цены 5 000 / 10 000 ₽/мес при неподключённой оплате. → `01 §8`

**Практическое следствие:** не начинать клиентский кабинет, подписки и онбординг до решения `OQ-ARCH-01`. Это работа по неизвестному ТЗ. → `14`

**«AI» в проекте нет.** `bot/learning/` — детерминированные правила и EMA-скаляр уверенности (α=0.15, границы [0.05, 0.95]). Запрещённые формулировки: «AI», «машинное обучение», «нейросеть», «байесовский», «институциональная платформа». → `06 §4`, `12 §3`

## 6. Технический долг, который нельзя «попутно исправить»

- торговое окно в наивном локальном времени, лог заявляет UTC (`A-04`);
- два Telegram-бота, уникальная функциональность в legacy (`A-05`);
- дубли: `bot/auth/` vs `bot/security/`, `/api/v1` vs `/api/v2`, две схемы БД, два `rules.yaml` (`A-06`, `B-04`);
- решение не воспроизводимо: версия правил не сохраняется (`B-03`);
- 3 high-severity CVE в npm-дереве (`S-03`) — `npm audit fix --force` **запрещён**;
- дрейф дизайн-токенов сайт ↔ Dashboard (`Q-02`).

Каждый пункт — отдельная задача с ID. Трогать в рамках чужой задачи нельзя.

## 7. Сильные стороны — ломать запрещено

- контрактный слой `/api/v2`: envelope, коды ошибок, валидация всех параметров с отказом вместо тихого fallback;
- безопасность Python-части: серверные сессии, Argon2id, CSP с per-request nonce, двойной CSRF, двухуровневая защита от подбора, идемпотентность, audit trail с переходами состояния, AES-256-GCM;
- ноль `TODO`/`FIXME`/`HACK` на 258 файлов кода;
- **честность контента сайта** — все конкретные технические заявления проверены построчно и подтверждаются кодом, включая четыре добровольных раскрытия невыгодных ограничений. Это ключевой актив продукта (`P-07`).
