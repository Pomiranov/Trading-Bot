# Часть 1: вскрытие сломанной формы. Молча или громко — УСТАНОВЛЕНО

## Механизм

Записанная в коммите `0e9e078` форма:

```
git rev-list --all          | xargs git grep -l --fixed-strings -e "$TOK" --
git rev-list --all --reflog | xargs git grep -l --fixed-strings -e "$TOK" --
```

`xargs` дописывает свои аргументы **в конец** команды, то есть **после** `--`.
Синтаксис `git grep` таков: `git grep [опции] <шаблон> [<ревизия>…] [[--] <путь>…]`
— ревизии стоят **до** `--`, а всё **после** `--` читается как **pathspec**.

Значит команда исполнялась как «искать в РАБОЧЕМ ДЕРЕВЕ, ограничившись файлами с
именами `994ae03…`, `7c163f5…`, …». Таких файлов нет ⇒ область пуста ⇒ результат
пуст **при любом содержимом репозитория**.

## Отказ был МОЛЧАЛИВЫМ. Замерено, а не выбрано

`git version 2.54.0.windows.1`. Шаблон замера — `утренн`, заведомо присутствующий
(15 файлов в `HEAD`). Секрет в замере не участвовал.

| что мерилось | результат |
|---|---|
| stderr при ревизиях после `--`, одиночный `git grep` | **0 байт** |
| stderr при ревизиях после `--`, через `xargs` | **0 байт** |
| код возврата `git grep`, ревизии после `--` | **1** |
| код возврата `git grep`, шаблона нет нигде (нормальная форма) | **1** — тот же |
| код возврата `xargs`, сломанная форма, шаблон ЗАВЕДОМО есть | **123** |
| код возврата `xargs`, рабочая форма, шаблона нет нигде | **123** — тот же |
| код возврата `xargs`, рабочая форма, шаблон есть | **0** |
| был ли stderr подавлен в записанной форме `0e9e078` | **нет**: `2>` в ней отсутствует |

Контроль, что дело именно в позиции `--`:

```
git grep -l -e 'утренн' HEAD --                       → 15 файлов
git grep -l -e 'утренн' -- HEAD                       →  0
git rev-list --all | xargs git grep -l -e 'утренн' -- →  0
git rev-list --all | xargs git grep -l -e 'утренн'    →  1105 пар (ревизия, путь)
```

## Урок: МОЛЧАЛИВЫЙ НОЛЬ, класс правила 12. Не «громкий отказ в шуме»

stderr **был виден** — перенаправления в записанной форме нет — **и был пуст**.
Никакого сообщения, которое можно было бы потерять в шуме, не существовало.

**И это ХУЖЕ простого молчания.** Код возврата сломанной формы (`git grep` = 1,
`xargs` = 123) **совпадает с кодом легитимного «ничего не найдено»**. То есть
сломанную форму нельзя было отличить от чистого репозитория:

- ни глазом — вывод пуст в обоих случаях;
- ни автоматической проверкой — код возврата одинаков;
- ни сравнением с ожиданием — ожидался как раз ноль.

Единственный способ различить их — **показать форму срабатывающей на заведомо
подсаженном случае**, то есть правило 12. Оно и не применялось.

## Почему это не поймала «третья форма»

Довод при её введении был верен: «`--all` не покрывает недостижимые объекты, а
отозванный коммит остаётся в reflog». Но:

1. форма молчала (см. выше), поэтому довод не проверялся;
2. **сам довод недостаточен.** Замерено на подсадке: `--all --reflog` **не
   покрывает** объект, снятый `git commit --amend` после истечения reflog. Форма,
   исправленная только по `--`, дала бы **2 из 3** — и снова прочиталась бы как
   «чисто».

Замер по боевому репозиторию подтверждает то же числом: **2194 объекта в базе,
2187 достижимы из `--all`, 2187 из `--all --reflog`, 7 объектов вне обеих
областей** (5 блобов и 2 дерева, все подтверждены `git fsck --unreachable`;
крупнейший блоб — 788 155 байт). Ни одна форма на основе перечня ссылок их не
видит.
