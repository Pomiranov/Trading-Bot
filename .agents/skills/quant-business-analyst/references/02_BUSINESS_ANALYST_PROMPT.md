## Продукт и бизнес-модель

QuantFlow **не предсказывает рынок** и **не использует ML/LLM для генерации сигналов**.
Он измеряет, какие проверенные правила работают сейчас, и распределяет капитал строго
по статистическому доверию.

- Каждая стратегия имеет `confidence ∈ [0.05, 0.95]`, обновляемое по Байесу после каждой
  сделки. Размер позиции — прямая функция confidence.
- `MIN_TRADES_FOR_CONFIDENCE = 20` (до 20 сделок — базовый уровень, без доверия),
  `CONFIDENCE_LEARNING_RATE = 0.15`, границы 0.05 / 0.95 — никогда не 0 и не 1.
- Статусы стратегии: `LIVE` · `PAPER` · `FROZEN` (капитал не распределяется, история
  сохраняется) · `HYPOTHESIS`. Замороженная стратегия **не удаляется**.
- Рынки: MOEX через T‑Invest (sandbox + production), Финам (в разработке), крипто через
  Bybit (spot + derivatives), Paper Trading — всегда доступен.
- Тарифы: **Sandbox** бесплатно 7 дней (только песочница, до 2 материалов) · **Live**
  5 000 ₽/мес (маршрут T‑Invest, до 10 материалов) · **Premium** 10 000 ₽/мес (до 50
  материалов, расширенный аудит, приоритет на Bybit/Финам).
- Стадия: **закрытая бета**, доступ открывается вручную. Дисклеймер: платформа для
  образовательных и исследовательских целей.

Из этого следуют два продуктовых ограничения, которые ты обязан защищать в каждом промте:

1. **Честность данных важнее полноты экрана.** Никогда не подставлять плейсхолдер вместо
   отсутствующих данных. Нет метрики — писать «н/д» с типизированной причиной, а не «0».
2. **Никакой функциональности сверх запрошенной.** Проект уже отказывался
   изобретать страницы под чужой бриф (`docs/DASHBOARD_QUALITY_LOG.md`, «Scope note»).
   Новая сущность требует отдельного решения, а не попутного добавления.

## База данных — единственный источник истины

**Авторитетная схема: `bot/qf_platform/schema.py`.** 21 таблица:

```
trades · candles · paper_accounts · paper_positions · paper_trades
equity_snapshots · trading_signals · backtest_runs · news · system_events
trade_feedback · belief_system · hypotheses · skipped_signals · forward_state
dashboard_users · dashboard_sessions · dashboard_login_attempts
action_idempotency · audit_events · schema_migrations
```

`quantflow_schema.sql` в корне содержит только 5 таблиц и **не является авторитетным** —
не ссылайся на него как на схему.

**Миграции.** `schema.py` — данные, `python -m qf_platform.migrate` — единственный
исполнитель. `--check` только отчёт. DDL при импорте отключён
(`QF_ALLOW_STARTUP_DDL=0` по умолчанию). Создание оператора:
`python -m qf_platform.migrate --create-user NAME --role <observer|operator|administrator> [--trading-authorized]`.

**Что важно про legacy:** таблица `trades` — историческая. Портфель, позиции, сделки и
equity читаются из `paper_accounts` / `paper_positions` / `paper_trades` /
`equity_snapshots`. Сигналы — из `trading_signals`, а не из `trades + trade_feedback`.
Системный лог — из `system_events`, а не из `news`. Если задача касается метрик —
явно фиксируй в промте, из какой таблицы читать.

## API: два уровня, разные правила

**`/api/v2/*` — контрактный слой.** Правило, записанное в docstring
`bot/ui/api/v2/__init__.py`: маршруты **тонкие по определению** — разбирают и валидируют
параметры, вызывают **один** сервис, оборачивают результат в envelope. **Ни SQL, ни
финансовой арифметики, ни ветвления по форме данных.** Именно это делает принцип
«одна метрика — один авторитетный расчёт» проверяемым, а не декларативным.
Операционный дашборд общается **только** с v2.

Существующие read-маршруты v2 (все под `@require_auth`):
`/environment` `/faults` `/health` `/equity` `/equity/underwater` `/drawdown`
`/accounts` `/portfolio` `/positions` `/trades` `/trades/learning` `/statistics`
`/statistics/distribution` `/analytics/daily` `/signals` `/strategies`
`/strategies/<id>` `/strategies/decisions` `/hypotheses` `/risk`

**`/api/*` и `/api/platform/*` — v1 legacy.** Оставлены для Telegram Mini App и процесса
бота, GET‑ы сделаны read-only. Новую функциональность дашборда сюда не добавляют.

**Контракты — `bot/qf_platform/contracts.py`:** `envelope(data, meta)`, `Meta`,
`ApiError(ErrorCode)`, `clamp_limit`. 14 кодов ошибок, каждый с безопасным русским
текстом, никогда не интерполируемым внутренностями:

```
UNAUTHENTICATED · FORBIDDEN · CSRF_INVALID · READ_ONLY_MODE · RATE_LIMITED
VALIDATION_FAILED · NOT_FOUND · CONFLICT · DB_UNAVAILABLE · SCHEMA_OUT_OF_DATE
BROKER_UNAVAILABLE · UPSTREAM_TIMEOUT · INTERNAL · NOT_IMPLEMENTED
```

`DB_UNAVAILABLE` и `SCHEMA_OUT_OF_DATE` разделены намеренно: «нет базы» и «база старее,
чем читает дашборд» — разные отказы. Их слияние в общий 500 и было причиной
«четыре панели вечно грузятся».

## Роли, права и рубильники

Роли: `observer` (читать всё) · `operator` (пауза/запуск движка, переподключение,
подтверждение инцидента, бэктест) · `administrator` (+ учётные данные, лимиты,
стратегии, журнал аудита).

`trading_authorized` — **отдельный флаг, не роль**: администратор конфигурации не может
закрыть позицию только в силу роли.

Права (`bot/security/permissions.py`): `VIEW` `VIEW_AUDIT` `ENGINE_CONTROL`
`BROKER_RECONNECT` `ACKNOWLEDGE_FAULT` `RUN_BACKTEST` `RUN_LEARNING_CYCLE`
`MANAGE_CREDENTIALS` `MANAGE_LIMITS` `MANAGE_STRATEGIES` `MANAGE_USERS`
`EXECUTE_SIGNAL` `CLOSE_POSITION` `OPEN_POSITION` `SWITCH_TO_LIVE`.

Пароли: Argon2id (fallback scrypt), алгоритм записан в самом хеше — переход прозрачен.
Пароля по умолчанию нет ни в коде, ни в конфигурации.

CSRF: session-bound токен в читаемой cookie `qf_csrf`, отражается заголовком
`X-CSRF-Token`. Это **header-схема, не скрытое поле** — проверка «есть ли input с
csrf?» даёт ложноотрицательный результат.

Рубильники, по умолчанию **выключенные**:

| Переменная | По умолчанию | Значение |
|---|---|---|
| `QF_DASHBOARD_READ_ONLY` | `0` | режим только для чтения |
| `QF_DASHBOARD_AUTOSTART_ENGINE` | `0` | автостарт торгового движка |
| `QF_DASHBOARD_ALLOW_TRADING_ACTIONS` | `0` | исполнение сигнала, закрытие позиции |
| `QF_DASHBOARD_ALLOW_LIVE` | `0` | переключение в live |
| `QF_ALLOW_STARTUP_DDL` | `0` | миграция при старте (не рекомендуется) |
| `QF_HTTPS` / `QF_INSECURE_COOKIES` | `0` / `0` | HSTS и `Secure` на cookie |
| `QF_SESSION_TTL_SECONDS` | `28800` | скользящий срок сессии |
| `QF_LOGIN_MAX_FAILURES` / `QF_LOGIN_WINDOW_SECONDS` | `5` / `300` | rate limit входа |
| `QF_ACCOUNT_LOCK_AFTER` / `QF_ACCOUNT_LOCK_MINUTES` | `10` / `15` | блокировка аккаунта |
| `QF_DASHBOARD_DEBUG` | `0` | запрещён при host ≠ loopback |

`QF_DASHBOARD_READ_ONLY=1` отклоняет запись **на уровне соединения SQLAlchemy** — ошибка
в сервисе не может превратиться в запись. Разрешена запись только в инфраструктурные
таблицы (`dashboard_sessions`, `dashboard_login_attempts`, `dashboard_users`,
`audit_events`, `system_events`, `action_idempotency`) — ни одной доменной среди них.

## Инварианты — то, что нельзя откатывать

Записано в `design/DASHBOARD_UIUX_AUDIT.md` §12, потому что каждый пункт закрывает
конкретный дефект прошлой сборки и каждый выглядит накладными расходами для того,
кто не видел, что было до. **Включай релевантные пункты в раздел «Инварианты»
каждого промта:**

- Решение **copy-don't-import** для дизайн-токенов и его письменное обоснование.
- Линтер токенов и все 18 его правил.
- Обязательный `<caption>` у таблиц.
- `chartPanel` принимает `summary` и `tableRows` **аргументами конструктора**, а не
  опциональными дополнениями.
- `confidenceValue` **не может** отрисоваться без размера выборки.
- `freshnessMeta` **на срез**, а не один глобальный timestamp.
- Ограниченный shimmer; **ноль бесконечных анимаций**; `prefers-reduced-motion` уважается.
- Возможность отключить горячие клавиши.
- Блок `forced-colors`.
- Типизированные коды причин пустоты: `emptyReasonText(code)` в `app/i18n.js` — пустые
  состояния управляются **кодом из контракта данных**, а не строкой на месте отрисовки.
  «Сделок пока нет», «Нет сделок за выбранный период», «Не удалось загрузить» и «База
  данных недоступна» структурно не могут слиться в одно «Нет данных».
- Принцип «одна метрика — один авторитетный расчёт»; тонкость слоя v2.
- Отсутствие side effects при импорте модулей (`create_app()` — единственное место сборки).
