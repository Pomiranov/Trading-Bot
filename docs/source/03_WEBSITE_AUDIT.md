<a id="w-01"></a>
### [W-01] Единственный конверсионный путь по умолчанию не сохраняет заявку

**Статус:** VERIFIED
**Критичность:** Critical
**Приоритет:** P0
**Компонент:** `website/src/lib/beta/adapter.ts`, `src/app/api/beta/route.ts`
**Доказательство:**
- `getBetaAdapter()` (`adapter.ts`): возвращает `webhookAdapter` **только** если `process.env.BETA_ADAPTER === "webhook"` **и** задан `BETA_WEBHOOK_URL`; иначе — `consoleAdapter`.
- `website/.env.example` задаёт `BETA_ADAPTER=console`, `BETA_WEBHOOK_URL` не задан вовсе.
- `consoleAdapter.submit()` логирует замаскированный адрес (`a***@domain`) и возвращает `{ delivered: false }`. Комментарий в коде прямо говорит: «signup received, NOT stored (no destination configured)».
- UI обрабатывает это корректно: при `delivered: false` показывается `accessForm.successUndelivered` — «Приём заявок ещё не подключён на этом стенде, поэтому адрес нигде не сохранён».
**Файлы и маршруты:** `POST /api/beta`, `website/src/lib/beta/adapter.ts`, `website/src/components/sections/access/access-form.tsx`
**Текущее поведение:** На стенде без `BETA_WEBHOOK_URL` заявки не сохраняются нигде. Пользователь честно об этом уведомляется, но лид теряется.
**Ожидаемое поведение:** На production-деплое `BETA_ADAPTER=webhook` + рабочий `BETA_WEBHOOK_URL`; заявки попадают в место, которое кто-то читает.
**Влияние на пользователя:** Пользователь, заполнивший форму, видит сообщение, что его адрес не сохранён, и должен написать «напрямую» — но контакт для «напрямую» на сайте не указан явно (`footer.linkContact` ведёт на `#access`, то есть на ту же форму).
**Влияние на бизнес:** **Прямая потеря 100 % лидов** при незаданной переменной. Это единственная конверсионная точка на сайте.
**Техническое влияние:** Архитектура адаптера правильная — проблема исключительно конфигурационная.
**Корневая причина:** Деплой-конфигурация не завершена; отсутствует чеклист production-переменных.
**Рекомендация:** (1) Задать `BETA_ADAPTER=webhook` + `BETA_WEBHOOK_URL` на production до любого трафика. (2) Добавить в `footer` реальный контакт (email/Telegram) как fallback. (3) Рассмотреть fail-loud: если `NODE_ENV=production` и адаптер `console` — писать `console.error` при старте.
**Зависимости:** [W-02] (тот же чеклист переменных)
**Оценка объёма:** XS (конфигурация) / S (с fallback-контактом)
**Критерии приёмки:** POST на `/api/beta` в production возвращает `delivered: true`; тестовая заявка найдена в приёмнике; на сайте есть прямой контакт.
**Roadmap ID:** RM-P0-006

### [W-02] `robots.txt` и `sitemap.xml` отдают placeholder-домен; дефолты `SITE_URL` расходятся между файлами

**Статус:** VERIFIED
**Критичность:** High
**Приоритет:** P0
**Компонент:** SEO (`website/src/app/robots.ts`, `sitemap.ts`, `[locale]/layout.tsx`)
**Доказательство (живой вывод):**
```
$ curl -s http://localhost:3000/robots.txt
User-Agent: *
Allow: /
Sitemap: https://quantflow.example/sitemap.xml

$ curl -s http://localhost:3000/sitemap.xml
<loc>https://quantflow.example/en</loc> …
```
- `robots.ts:4` и `sitemap.ts:4`: `process.env.NEXT_PUBLIC_SITE_URL ?? "https://quantflow.example"`
- `[locale]/layout.tsx:55`: `process.env.NEXT_PUBLIC_SITE_URL ?? "https://quantflow.app"` ← **другой дефолт**
- `website/.env.example` задаёт `NEXT_PUBLIC_SITE_URL=https://quantflow.example` — то есть даже пример конфигурации содержит placeholder.
**Файлы и маршруты:** `/robots.txt`, `/sitemap.xml`, `src/app/robots.ts:4`, `src/app/sitemap.ts:4`, `src/app/[locale]/layout.tsx:55`
**Текущее поведение:** При незаданной переменной sitemap объявляет URL на несуществующем домене, а canonical/OG-теги — на третьем домене. Расхождение дефолтов означает, что забытая переменная даёт **две разные неправильные конфигурации одновременно**.
**Ожидаемое поведение:** Один источник значения; при отсутствии переменной в production — явная ошибка сборки, а не тихий placeholder.
**Влияние на пользователя:** Ссылки в поиске и превью в соцсетях ведут в никуда.
**Влияние на бизнес:** Индексация фактически сломана; OG-превью не работают → падает CTR из соцсетей и мессенджеров (критично, т. к. распространение идёт через Telegram).
**Техническое влияние:** Три места для одной константы.
**Корневая причина:** Дефолт скопирован в три файла и разошёлся.
**Рекомендация:** Вынести `SITE_URL` в один модуль (`src/lib/seo/site-url.ts`), сделать `throw` при отсутствии переменной в production-сборке, задать переменную на деплое.
**Зависимости:** [W-01]
**Оценка объёма:** S
**Критерии приёмки:** `curl /robots.txt` и `/sitemap.xml` на production содержат реальный домен; `grep -c "quantflow.example" src/` = 0; сборка падает без переменной в prod.
**Roadmap ID:** RM-P0-007

**Доказательство:** После открытия панели (реальный клик, 390 px) `document.activeElement` остаётся `BODY`. Панель при этом содержит 7 tabbable-элементов. Атрибуты `role="dialog"` и `aria-modal` на панели отсутствуют (`role: null`, `ariaModal: null`), присутствует только `aria-label="Навигация"`.
**Файлы и маршруты:** `/ru` на ширине < 1024 px
**Текущее поведение:** Пользователь клавиатуры/скринридера открывает меню, но фокус остаётся на триггере/body; чтобы дойти до пунктов, нужно продолжать Tab. Фокус не заперт в панели — Tab уводит на контент под ней.
**Ожидаемое поведение:** По паттерну модального меню: при открытии фокус переходит на первый пункт (или контейнер), Tab циклится внутри панели, Escape закрывает и возвращает фокус.
**Влияние на пользователя:** Затруднённая навигация для пользователей клавиатуры и скринридеров на мобильных.
**Влияние на бизнес:** Риск по доступности; для финансового продукта требования к a11y обычно строже.
**Техническое влияние:** Небольшая правка; **половина паттерна уже сделана правильно** — Escape и возврат фокуса работают.
**Корневая причина:** Реализован закрывающий контур, но не открывающий.
**Рекомендация:** Добавить перевод фокуса на первый пункт в эффекте открытия + focus trap; выставить `role="dialog"` и `aria-modal="true"`. Учесть, что панель — не полноэкранная, поэтому `aria-modal` требует проверки со скринридером.
**Зависимости:** —
**Оценка объёма:** S
**Критерии приёмки:** При открытии фокус внутри панели; Tab не покидает панель; Escape закрывает и возвращает фокус (регресс-тест на существующее поведение).

Это ожидаемо для копии, но означает, что при сборке в окружении без `.git` (типовой Docker-билд) `NEXT_PUBLIC_BUILD_SHA` станет `"dev"`, и `footer.buildLabel` покажет `dev` вместо коммита. На Vercel сработает `VERCEL_GIT_COMMIT_SHA`. Мелочь, но footer заявляет «Сборка» как признак прозрачности.

## Уровень уверенности аудита

**Высокий** для структуры, маршрутов, адаптивности на всех 5 разрешениях, семантики, статических гейтов, bundle-размеров, SEO-конфигурации и сверки контента с кодом — всё проверено на живом сайте и в production-сборке.
**Средний** для доступности — проверены landmarks, контраст (по документированным токенам), tap-targets, клавиатурная работа мобильного меню; полный аудит скринридером (VoiceOver/NVDA) не проводился.
**Низкий** для реальной производительности (Core Web Vitals) и кросс-браузерности (Safari/Firefox/iOS) — измерялось только в Chromium на dev-сервере.
