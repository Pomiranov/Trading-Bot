## Назначение документа

Проект разрабатывается через несколько независимых чатов и AI-агентов. Каждый видит только свой контекст, не знает, что делают остальные, и не помнит предыдущих сессий. Этот документ задаёт границы, чтобы параллельная работа не приводила к конфликтам и противоречиям.

**Главный риск при такой модели** — не ошибка в коде, а **расхождение**: два агента по-разному решают одну задачу, правят один файл, вводят разную терминологию или принимают несогласованные архитектурные решения. Правила ниже направлены прежде всего против этого.

## Обязательные правила для всех направлений

Эти правила применяются к каждому чату **без исключений**.

### 1. Начало любой сессии

```bash
git rev-parse --show-toplevel      # подтвердить фактический корень
git rev-parse --abbrev-ref HEAD    # подтвердить ветку
git rev-parse --short HEAD         # зафиксировать commit
git status --porcelain             # убедиться, что нет незакоммиченных чужих правок
```

**Никогда не полагайтесь на путь из документации.** `CLAUDE.md` на момент аудита указывал неверный корень (`Documents/GitHub/Trading-Bot` вместо `Downloads/Trading-Bot-merge-learning-nik`) и неверную ветку. Фактический корень определяется только `git rev-parse --show-toplevel`.

Если `git status` показывает незакоммиченные изменения, которых вы не делали — **не трогайте эти файлы** и сообщите владельцу.

### 2. Source of Truth

**Приоритет источников, от высшего к низшему:**
1. Текущий код.
2. Документы `docs/source/` (этот Source Pack).
3. Всё остальное — **справочно, с проверкой**.

Документы из списка «не считать актуальными» ([13](13_STALE_DOCUMENTS_REGISTER.md)) использовать нельзя как основание для решений.

### 3. Единая терминология

Обязательна к использованию во всём коде, коммитах и документации:

| Термин | Значение | Чем **не** является |
|---|---|---|
| **Оператор** (operator) | Пользователь Dashboard из `dashboard_users`, управляющий установкой | Не клиент, не подписчик |
| **Клиент** (client) | Конечный покупатель продукта | **Не существует в коде на момент аудита** |
| **Движок** (engine) | Торговый цикл `bot/main.py` + `services/bot_engine.py` | Не Dashboard, не бот |
| **Уверенность** (confidence) | Скаляр в `belief_system`, EMA с коэф. 0.15, границы [0.05, 0.95] | **Не** вероятность, **не** ML-предсказание, **не** байесовская величина |
| **Правила** (rules) | Декларативные YAML в `knowledge/rules/rules.yaml` | Не модель, не стратегия целиком |
| **Песочница** (sandbox) | `TINKOFF_SANDBOX=true` и/или paper-торговля | Не «демо-режим интерфейса» |
| **Paper trading** | Симулированное исполнение в `paper_*` таблицах с комиссией и проскальзыванием | Не бэктест |
| **Live** | `TINKOFF_SANDBOX=false`, реальные деньги | Не «продакшн-окружение» |
| **Платформенный слой** | `bot/qf_platform/` — репозитории, сервисы, контракты | Не Flask-приложение |
| **v2** | `/api/v2` — актуальный контракт | — |
| **v1 / legacy** | `/api/*` и `/api/platform/*` | — |

**Запрещённые формулировки** (они уже привели к оверклеймам в `README.md`): «AI», «машинное обучение», «нейросеть», «байесовский», «институциональная платформа» — применительно к текущей системе. В проекте **нет** ни одной ML-библиотеки и ни одного байесовского вычисления ([06 §4](06_BACKEND_DATA_AND_INTEGRATIONS_AUDIT.md)).

### 4. Единая Roadmap и единые ID задач

- Единственная актуальная Roadmap — [11](11_MASTER_ROADMAP.md). `design/ROADMAP.md` устарел.
- Новые задачи получают ID формата `RM-P<приоритет>-<номер>` и добавляются **в [11](11_MASTER_ROADMAP.md)**, а не в локальные списки.
- Каждый коммит, закрывающий задачу, упоминает её ID в сообщении.
- ID findings (`A-`, `W-`, `D-`, `T-`, `B-`, `S-`, `Q-`, `P-`, `X-`) неизменны — на них ссылаются все документы.

### 5. Запрет параллельного изменения одних файлов

**Файлы повышенного риска конфликта.** Прежде чем править любой из них, убедитесь, что этим не занимается другое направление:

| Файл | Основной владелец | Кто ещё может затронуть |
|---|---|---|
| `bot/main.py` | Trading Engine | Telegram Bot (уведомления), Backend |
| `bot/qf_platform/schema.py` | Backend and API | Trading Engine, Security |
| `bot/security/guards.py` | Security | Backend, Trading Engine |
| `bot/ui/app_factory.py` | Backend and API | Security |
| `website/messages/{ru,en}.json` | Website and Marketing | Product Strategy |
| `website/src/styles/tokens/*` | Frontend Architecture | Dashboard UI/UX (через дрейф токенов) |
| `bot/ui/static/css/tokens.css` | Dashboard UI/UX | Frontend Architecture |
| `knowledge/rules/rules.yaml` | Trading Engine | AI/ML and Data |
| `.env.example` | DevOps | все |
| `requirements.txt`, `package.json` | DevOps | все |
| `CLAUDE.md`, `docs/source/*` | Documentation | все |

**Правило:** одно направление — один владелец файла на время задачи. При необходимости кросс-правки — согласование, указанное в разделе направления.

### 6. Фиксация архитектурных решений

Любое решение, влияющее более чем на один модуль, оформляется как ADR в `docs/adr/` (формат уже существует — `website/docs/adr/0001-monogram.md`). ADR обязателен для:
- модели доступа ([OQ-ARCH-01](14_OPEN_QUESTIONS_AND_DECISIONS.md));
- срока удаления `/api/v1` ([OQ-ARCH-02]);
- дефолтного `EXECUTION_MODE` ([OQ-TRADE-01]);
- принятия риска по CVE ([OQ-SEC-01]);
- модели согласия на трекинг ([OQ-LEGAL-01]).

### 7. Обязательные проверки перед сдачей результата

Минимум, применимый к соответствующей части:

```bash
# Сайт
cd website && npm run typecheck && npm run lint && npm run check && npm run build

# Python
python3 -m pytest tests/
python -m qf_platform.migrate --check      # безопасно, только читает

# Dashboard
node bot/ui/static/app/format.test.mjs
node bot/ui/static/check-dashboard-tokens.mjs   # ВНИМАНИЕ: на момент аудита падает (Q-02)
```

Известные красные гейты на момент аудита: `check-dashboard-tokens.mjs` (exit 1), `qa:landing` (exit 2, нет Playwright). **Если ваш гейт падал до вашей правки — не «исправляйте» это молча в рамках чужой задачи; сообщите и сошлитесь на RM-P2-015 / RM-P1-020.**

### 8. Передача результатов и обновление Source

При завершении задачи сообщайте:
1. Commit(ы) и ветку.
2. Закрытые ID задач и findings.
3. Результаты обязательных проверок (exit codes).
4. Что **не** сделано и почему.
5. Какие документы Source требуют обновления.

**Значимое изменение обязывает обновить Source Pack.** Значимым считается: изменение схемы БД, добавление/удаление маршрута, изменение модели аутентификации, изменение поведения торгового цикла, изменение заявлений на сайте, закрытие любого Launch Blocker.

### 9. Запреты, действующие для всех

- Не коммитить `.env`, `bot/data/credential_vault.json`, любые секреты. (Проверено: сейчас всё корректно в `.gitignore`.)
- Не выполнять `python -m qf_platform.migrate` без `--check` на боевой БД без согласования.
- Не выполнять `npm audit fix --force` — он тянет мажорный апгрейд Next ([S-03](07_SECURITY_PRIVACY_AND_COMPLIANCE_AUDIT.md)).
- Не менять `TINKOFF_SANDBOX` на `false` без явного согласования — это переключение на реальные деньги.
- Не удалять существующие документы; помечать DEPRECATED ([13](13_STALE_DOCUMENTS_REGISTER.md)).
- Не ослаблять заявления честности на сайте и не добавлять цифры результата — это ключевой актив продукта ([P-07](09_PRODUCT_UX_MARKETING_AND_MONETIZATION_AUDIT.md)).
- Не запускать Telegram-бота, если может работать другой экземпляр — Telegram допускает один polling-консьюмер на токен ([A-05](02_REPOSITORY_AND_SYSTEM_ARCHITECTURE_AUDIT.md)).

**Source:** [02](02_REPOSITORY_AND_SYSTEM_ARCHITECTURE_AUDIT.md), [06](06_BACKEND_DATA_AND_INTEGRATIONS_AUDIT.md), [10 §9-16](10_CURRENT_DEVELOPMENT_STATUS.md).
**Может изменять:** перечисленное выше.
**Согласование с:** Telegram Bot (RM-P0-002), Security (идемпотентность, аудит — RM-P0-008), Backend (`schema.py`), AI/ML (`rules.yaml`, `belief_system`), QA (тесты).
**Входные данные:** решение по `EXECUTION_MODE`, порог kill switch.
**Ожидаемые результаты:** RM-P0-002, RM-P0-008, RM-P1-006, RM-P1-014, RM-P2-004, RM-P2-017.
**Обязательные проверки:** `pytest tests/`; **обязательно** прогон в sandbox перед любым изменением, влияющим на исполнение; проверка, что `TINKOFF_SANDBOX` не изменён.
**Критерии завершения:** тест на изменённое поведение; sandbox-прогон без расхождений с брокером; запись в `audit_events` присутствует.

**Особые правила — это направление с наивысшим риском:**
- **Никогда** не переключать `TINKOFF_SANDBOX=false` в рамках задачи без явного согласования.
- Любое изменение, влияющее на отправку заявок, требует теста **до** внедрения.
- `place_market_order` глотает исключения и возвращает `None` — учитывать при любой правке пути исполнения; реконсиляция позиций (`bot/main.py:_reconcile_positions_with_broker`) существует именно из-за этого и её нельзя ломать.
- Правка `knowledge/rules/rules.yaml` меняет торговое поведение. Убедиться, что правится `knowledge/rules/rules.yaml`, а **не** дубль `knowledge/rules.yaml` ([B-04](06_BACKEND_DATA_AND_INTEGRATIONS_AUDIT.md)).

### 9. Security and Compliance

**Ответственность:** аутентификация, авторизация, защита данных, заголовки, зависимости, соответствие требованиям.
**В scope:** `bot/security/**`, `bot/auth/**`, CSP, cookies, CSRF, идемпотентность, аудит, шифрование секретов, уязвимости зависимостей, юридический контур (координация с внешним юристом).
**Не в scope:** продуктовые решения, торговая логика (кроме её защиты).
**Source:** [07](07_SECURITY_PRIVACY_AND_COMPLIANCE_AUDIT.md), [02 §A-07](02_REPOSITORY_AND_SYSTEM_ARCHITECTURE_AUDIT.md).
**Может изменять:** `bot/security/**`, `bot/auth/**`, `website/next.config.ts` (заголовки — согласование с Frontend), `bot/security/http_middleware.py`.
**Согласование с:** Backend (`guards.py` используется роутами), Frontend Architecture (CSP в middleware), Telegram Bot (`initData`), DevOps (секреты, TLS), Product Strategy (юридические решения).
**Входные данные:** модель угроз, заключение юриста.
**Ожидаемые результаты:** RM-P0-005, RM-P0-008, RM-P1-011, RM-P1-013, RM-P1-016, RM-P1-017, RM-P1-018.
**Обязательные проверки:** `pytest tests/security_tests/`; `npm audit`; проба, что защищённые эндпоинты возвращают 401 без сессии; проверка заголовков живого ответа.
**Критерии завершения:** тесты безопасности зелёные; ни один защищённый маршрут не открыт анонимно; изменения заголовков проверены на живом ответе.

**Особые правила:**

## Уровень уверенности документа

**Высокий** для карты владения файлами и терминологии — выведены из фактической структуры репозитория, проверенной в этом аудите.
**Средний** для границ направлений — это предложенная организационная модель, а не наблюдённый факт; её следует скорректировать под фактический состав команды (который аудиту неизвестен). Если проект ведёт один человек, направления работают как чеклисты контекста, а не как роли.
