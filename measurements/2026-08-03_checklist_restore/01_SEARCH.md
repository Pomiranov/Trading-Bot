## 🚨 НАЙДЕН ДЕФЕКТ В ФОРМЕ ПОИСКА, которую велено было повторить

Форма, записанная в коммите `0e9e078` как доказательство отсутствия токена в
истории, **не работает**:

```
git rev-list --all          | xargs git grep -l --fixed-strings -e "$TOK" --
git rev-list --all --reflog | xargs git grep -l --fixed-strings -e "$TOK" --
```

`xargs` дописывает SHA **после** `--`, а всё, что стоит после `--`, `git grep`
читает как **pathspec**, не как ревизию. Поиск идёт по рабочему дереву,
ограниченному путями с именами вроде `994ae03…`, которых не существует ⇒ **ноль
всегда, независимо от содержимого**.

Контрольный замер, доказывающий это:

```
$ git grep -l -i -E 'утренн' HEAD --      →  15 файлов
$ git grep -l -i -E 'утренн' -- HEAD      →   0
$ git rev-list --all | xargs git grep -l -i -E 'утренн' --   →   0
$ git rev-list --all | xargs git grep -l -i -E 'утренн'      →  1105 (rev,путь)
```

**Следствие для §5 и хендоффа:** утверждение «в репозиторий токен НЕ утекал —
проверено тремя формами по 14 ссылкам и 127 коммитам, включая недостижимые
объекты» опирается фактически на **одну** форму — `git log --all -S"$TOK"
--pickaxe-all -- .`, которая корректна. Две другие возвращали ноль по построению.
Вывод мог остаться верным, но **доказательная сила заявлена втрое выше
фактической**. Не исправлено: решение за человеком.

Здесь применена исправленная форма — ревизии **до** `--`:
`git grep -l -i -E "<шаблон>" $(git rev-list --all)`.

## Все вхождения счёта «12» как приёмки блока A: ШЕСТЬ, не три

Получено предикатом
`(из[^0-9а-яА-Я]{1,3}12|ДВЕНАДЦАТЬ[^а-я]|двенадцать[^а-я]{0,3}пункт|12[^а-яА-Я]{0,4}пункт)`
по `HEAD -- docs/`, затем отброшены вхождения про «набор из 12 бумаг» (они про
тикеры, а не про пункты):

| # | место | текст |
|---|---|---|
| 1 | `docs/HANDOFF_2026-08-03.md:44` | `### Шаг 2 — приёмка блока A, ДВЕНАДЦАТЬ пунктов` |
| 2 | `docs/HANDOFF_2026-08-03.md:46` | `Счёт на сейчас: **2 из 12**` |
| 3 | `docs/PROJECT_STATE.md:2240` | `**Счёт по блоку A: 2 из 12**` |
| 4 | `docs/PROJECT_STATE.md:7930` | `**12 пунктов** (счёт **2 из 12**, пункт 12 провален 02.08)` |
| 5 | `docs/PROJECT_STATE.md:8010` | `**НЕ ВЫПОЛНЕНА: пройдено 2 пункта из 12**` |
| 6 | `docs/PROJECT_STATE.md:8094` | `двенадцать пунктов, пройдено 2 из 12` |

Плюс согласованное с ними `docs/PROJECT_STATE.md:8012` — «десять пунктов» не
проверено; `10 + 2 = 12`.

**Ни одно из шести не правится.** Длина собранного списка = 12 (11 найденных + 1
заглушка), значит число уже равно длине. Перенумерация была бы вредна отдельно:
на пункты 10, 11, 12 ссылаются ПО НОМЕРУ шесть мест
(`HANDOFF:41`, `PROJECT_STATE:2347, 7930, 8012, 8253, 8261`), и сдвиг номеров
сломал бы все шесть.

## Противоречие, которое сборка НЕ лечит

«Поправка 2» (`docs/PROJECT_STATE.md:1880`) называет **пунктом 7** формулировку
«строк `origin='backtest'` — ноль». Пункт 7 редакции 31.07 —
`powercfg /waketimers`. Две нумерации несовместимы, и какая верна, по документам
не устанавливается. В сборку взята та, что записана **элементом нумерованного
списка**, а не упомянута в прозе. Противоречие оставлено видимым в тексте
раздела; выбор между нумерациями — решение человека.
