## Шаги

### 1. BotFather — выпустить новый токен (~40 с)

1. открыть в Telegram чат с **@BotFather**;
2. отправить `/mybots` → выбрать бота проекта;
3. **API Token** → **Revoke current token**;
4. BotFather подтверждает и сразу выдаёт **новый токен** вида
   `8807xxxxxx:AAG…`. Скопировать целиком.

> **Отзыв мгновенный.** Старый токен перестаёт работать в ту же секунду, то есть
> с этого момента и до шага 2 сторож доставить ничего не сможет. Окно —
> секунды, но если между шагами что-то прервётся, помнить: молчание сторожа в
> это время ожидаемо и не является отказом.

### 2. `.env` — заменить значение (~30 с)

В `D:\Trading-Bot-Nik\.env` заменить строку:

```
TELEGRAM_TOKEN=<старое>
```

на новое значение. **Менять только эту строку.** `TELEGRAM_CHAT_ID` не трогать —
чат тот же, токен к чату отношения не имеет.

Файл в `.gitignore`, коммитить нечего.

### 3. Проверка, что новый токен работает (~30 с)

Из `D:\Trading-Bot-Nik`:

```powershell
.venv\Scripts\python.exe -c "import sys; sys.path.insert(0,'bot'); import notify; print('доставлено:', notify.send('проверка ротации токена 03.08'))"
```

**Ожидается:** `доставлено: True` и сообщение в том же чате.

* `False` + в логе `401 Unauthorized` — токен скопирован не целиком или с
  пробелом;
* `False` + `ConnectTimeout` — это сеть, а не токен: повторить через минуту.
  Именно этот класс отказа разбирался 02.08.

### 4. Проверка, что СТАРЫЙ токен мёртв (~20 с, необязательно, но дёшево)

```powershell
$old='<старое значение>'
try { (Invoke-RestMethod "https://api.telegram.org/bot$old/getMe" -TimeoutSec 10) } catch { "ожидаемо: $($_.Exception.Message)" }
```

**Ожидается `401 Unauthorized`.** Если приходит `200 OK` — отзыв не состоялся,
вернуться к шагу 1.
