## B1. Что такое Quant, одним экраном

Автоматический торговый оператор для MOEX. Путь от свечи до заявки — детерминированный
конвейер из 7 этапов:

```
01 CANDLE LOADER    OHLCV из MOEX ISS / Bybit API
02 INDICATOR ENGINE RSI · ATR · EMA · MACD · BB · ADX · VWAP · Stochastic · CCI
03 RULES ENGINE     правила из knowledge/rules.yaml → BUY/SELL/HOLD + score
04 BELIEF GATE      сверка сигнала с текущей уверенностью стратегии
05 RISK MANAGER     стоп по ATR · размер = f(уверенность) · дневной лимит
06 BROKER / PAPER   TinkoffClient · BybitClient · PaperEngine
07 MEMORY WRITER    результат сделки → пересчёт уверенности
```

Маркетинговая ценность этого списка: каждый этап можно назвать по имени реальной функции.
Это «Stripe-docs-grade» специфичность — сильнейший аргумент доверия у продукта, и он
бесплатный. Используй его вместо цифр.

**Аудитории лендинга (уже зафиксированы в копирайте):** новичок (песочница, ручное
подтверждение), трейдер (читаемые правила, измеряемая уверенность, риск до входа),
партнёр/разработчик (общий слой данных, шифрование, журнал), скептик (ни одной цифры
результата, замороженные стратегии на витрине, отсутствие kill switch названо прямо).

## B2. Уверенность и стратегии

- Диапазон `[0.05, 0.95]` — никогда не ноль и никогда не определённость.
- До 20 подтверждённых сделок уверенность не двигается.
- Скорость адаптации 0.15 (15% за сделку).
- Сигнал с уверенностью ниже 0.20 фиксируется в журнале, но не исполняется.
- Статусы стратегии: `LIVE` / `PAPER` (форвард) / `FROZEN` / `HYPOTHESIS` (кандидат).
- Замороженная стратегия не удаляется и остаётся на витрине. На сайте сейчас три:
  один форвард на живых данных с исполнением в песочнице и две замороженные
  («стабилизирована, но не вылечена», «на новых данных результат не подтвердился»).

## B3. Безопасность — что можно утверждать

| Утверждение | Точная формулировка |
|---|---|
| Вывод средств | В брокерском интерфейсе, которым пользуется Quant, метода вывода/перевода **нет как кода**. Права на вывод при подключении не нужны. |
| Риск-лимиты | Доля на позицию, дневной убыток, число позиций, стоп по ATR проверяются **до** обращения к брокеру. |
| Песочница | Клиент брокера стартует в sandbox. Переход к реальным деньгам — отдельный осознанный шаг. |
| Остановка | Пауза и стоп — из Telegram и Dashboard. Просадка **уведомляет**, но не останавливает. Автоматического kill switch нет. |
| Ключи | AES-256-GCM, файл с правами только владельца, шифрование включается мастер-ключом при развёртывании; изменения — в журнал аудита. Если мастер-ключ не задан, ключи остаются в `.env` — это нужно исправить до боевого запуска, и об этом говорим прямо. |
| Уверенность | Ограничена 0.05–0.95, никогда не становится определённостью. |

Формулировка-рамка, уже принятая в копирайте: «Ограничения ниже — не обещания, а свойства
кода. Там, где ограничение неполное, мы говорим об этом прямо».

## B7. Что действительно сломано в воронке (приоритеты маркетинга)

Проверено по коду. Это лучший бэклог для первых промтов.

1. **Заявки никуда не сохраняются.** Дефолтный адаптер — `consoleAdapter`: пишет
   замаскированный адрес в лог и возвращает `delivered: false`. Реальный приём включается
   `BETA_ADAPTER=webhook` + `BETA_WEBHOOK_URL`. Пока не включён, интерфейс обязан говорить
   «адрес нигде не сохранён» — эта честная ветка в копирайте уже есть
   (`accessForm.successUndelivered`). **Это критический блокер: любой лид сегодня теряется.**
2. **Нет подтверждающего письма.** Единственное подтверждение — состояние страницы,
   исчезающее при перезагрузке.
3. **Нет rate limiting на приёме заявок.** Только honeypot-поле.
4. **Юридической поверхности нет.** Ни политики, ни условий, ни риск-дисклеймера
   отдельной страницей. Для финансового продукта отсутствие — само по себе негативный
   сигнал. Текст пишет юрист, не Claude Code; в код идут только ссылки и разметка.
5. **OG-картинки нет.** Метаданные текстовые есть, `robots.ts`/`sitemap.ts` есть, а
   ассета для шеринга нет — а шеринг ссылкой и есть главный канал закрытого продукта.
6. **Нет события на клик по хедерному CTA и футеру** — `location` в `cta_clicked`
   свободная строка, значения надо назначить и замерить против нижнего CTA.
7. **Таксономия аналитики оборвана осознанно.** Редизайн переименовал все слаги секций,
   старые воронки в PostHog молча обнулились. Любой промт, меняющий `id` секции, обязан
   упомянуть последствия для сохранённых воронок.

## B9. Как писать для Claude Code (методика)

- **Сначала чтение, потом правка.** Всегда перечисляй файлы, которые надо прочитать, и
  что в них искать. Claude Code не должен угадывать API проекта.
- **Пути, а не описания.** «Секция тарифов» → `website/src/components/…/pricing-section.tsx`
  + ключи `pricing.*` в обоих `messages/*.json`.
- **Проверяемый DoD.** Не «сделай красиво», а «`npm run check` зелёный, контраст лида
  ≥ 4.5:1, замер `getComputedStyle` в отчёте».
- **Раздел «Не делать» обязателен.** Он экономит больше времени, чем всё остальное:
  именно там ты запрещаешь заодно отрефакторить кнопки, поменять токены или тронуть `bot/`.
- **Один промт — один связный PR.** Больше — разбивай и нумеруй.
