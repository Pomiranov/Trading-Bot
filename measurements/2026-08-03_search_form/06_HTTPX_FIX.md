# Шаг 1 перед ротацией: httpx/httpcore → WARNING. Приёмка обеими половинами

Единственная правка кода в этом заходе, разрешена явно. Дата 2026-08-03.

## Утечка ДЕЙСТВУЮЩАЯ, а не историческая — замер, не утверждение

| что | значение |
|---|---|
| отпечаток значения из `logs/forward_d1.log`, строки 1129–1130 | `sha256[:16] = 0ff78dc0aa43e2d0` |
| отпечаток значения в `.env` | `sha256[:16] = 0ff78dc0aa43e2d0` — **совпал** |

В логе лежит **боевой, действующий** токен, а не остаток прежнего. До 03.08 в
документах это стояло утверждением «токен утекает»; теперь это измеренная
величина. Сравнение сделано отпечатками, без печати значений — правило 16 §8.

## Половина 1: ДЕФЕКТ показан предикатом по файлу, не глазами

Прогон воспроизводит окружение боевого прогона дословно: тот же
`logging.basicConfig(level=logging.INFO)`, что в `run_forward_d1.py::main()`, и тот
же путь отправки `ui/telegram_bot.py::send_notification`.

```
ВХОЖДЕНИЙ ЗНАЧЕНИЯ В ВЫВОДЕ: 2
строк логгера httpx        : 2
номера строк со значением  : 3 4
```

Форма строк (значение вырезано, полный вывод — `07_LEAK_BEFORE_redacted.log`):

```
[INFO] httpx: HTTP Request: POST https://api.telegram.org/bot<ТОКЕН>/getMe      "HTTP/1.1 200 OK"
[INFO] httpx: HTTP Request: POST https://api.telegram.org/bot<ТОКЕН>/sendMessage "HTTP/1.1 200 OK"
```

Оба запроса вернули 200 — то есть путь рабочий, и утечка происходит на **успешной**
отправке, а не только на отказе. Маскировка `notify.py` здесь бессильна: она правит
текст исключения, а `httpx` логирует сам, минуя вызывающего.

## Половина 2: ПОСЛЕ правки — ноль при той же отправке

Тот же скрипт, тот же `basicConfig`, тот же вызов:

| замер | вхождений значения | строк логгера httpx |
|---|---|---|
| **до** правки | **2** | 2 |
| **после** правки | **0** | 0 |

Доставка не сломана: `отправка завершена`, код возврата 0. Полный вывод —
`08_LEAK_AFTER.log` (вырезать в нём нечего: значения там нет, проверено предикатом).

## Правка: одно место, и почему именно это

`bot/ui/telegram_bot.py`, сразу после `logger = logging.getLogger(__name__)`:

```python
for _noisy in ("httpx", "httpcore"):
    logging.getLogger(_noisy).setLevel(logging.WARNING)
```

**Почему НЕ в `bot/security/logging_config.py`**, хотя он озаглавлен «Centralized
logging setup»: `configure_logging()` вызывается **только** из
`security/bootstrap.py`, а тот — только из `main.py`. `run_forward_d1.py` ставит
себе `logging.basicConfig` сам и до bootstrap не доходит. Правка в
`logging_config.py` **не закрыла бы** утечку в `forward_d1.log` — это ровно тот
класс, который отзывался в этот же день: верное требование, реализованное
механизмом, который на нужном пути не исполняется.

Правка стоит в модуле, **владеющем протекающей зависимостью**
(python-telegram-bot 22.8 → httpx 0.28.1). Утечка невозможна без импорта этого
модуля, поэтому одно место покрывает все точки входа, какой бы `logging` они себе
ни ставили. Уровень поднимается до первого запроса: импорт предшествует отправке.

**Проверено, что других путей с токеном в URL нет:**

| путь | httpx? | токен в URL? |
|---|---|---|
| `bot/ui/telegram_bot.py::_send` → PTB `Bot` | да | **да — это и есть утечка** |
| `bot/notify.py::send` | нет, `requests`; токен маскируется в тексте ошибки | нет |
| `bot/tg/notifications/dispatcher.py::_push_sse` | да | нет: URL локальный, `http://127.0.0.1:<порт>/api/internal/push` |

## Боевой лог НЕ тронут — намеренно

Опыт писал в отдельный файл, а не в `logs/forward_d1.log`. Причина: на строки
**1129 и 1130** ссылаются четыре документа, и дописывание туда новых вхождений
сделало бы эти ссылки неверными. Замер до и после опыта:

```
вхождений в logs/forward_d1.log: 2, строки 1129 1130   (не изменилось)
```

Это отступление от буквы задания («оставляет вхождение значения в
`logs/forward_d1.log`») названо явно: механизм тот же — вывод процесса с тем же
`basicConfig`, — а цель отступления в том, чтобы не испортить цитируемую улику.

## Чего это НЕ закрывает

Долг остаётся открытым. Закрыт **один путь** утечки, а форма **тест-предиката** —
«ни один файл под `logs/` и `measurements/` не содержит значений
`TELEGRAM_TOKEN` и `DB_PASSWORD»` — не написана, и выбор между «только тест»,
«тест + сторож» и «тест + отдельная задача» за Ником. Уровень логирования
кто-нибудь вернёт, предикат — нет.

Срочность правки была не в этом, а в сроке: без неё ночной прогон **04.08 00:15**
записал бы в тот же лог **новый** токен, и ротация купила бы 14 часов.
