# Agent Responsibilities — какой агент какие задачи берёт

Этот документ распределяет задачи между **инструментами** (Claude Code, Codex, Gemini CLI, встроенный OpenHands Agent). Распределение по **предметным направлениям** (Website, Dashboard, Trading Engine, Security, …) задано в `docs/source/12_AGENT_WORKSTREAMS_AND_RESPONSIBILITIES.md` и здесь не дублируется.

Две оси независимы: Control Center выбирает **направление** по `docs/source/12` и **исполнителя** по этому файлу.

---

## Claude Code — `Claude-Code-Quant-Architecture`

**Берёт:**

- архитектурные решения и всё, что затрагивает более одного модуля;
- сложные межмодульные изменения (`bot/main.py` ↔ `qf_platform` ↔ `services`);
- системные рефакторинги, включая устранение дублей `A-06` (`bot/auth/` vs `bot/security/`, `/api/v1` vs `/api/v2`);
- security-sensitive задачи: аутентификация, сессии, audit trail, шифрование, CSP/CSRF;
- финальную техническую интеграцию результатов других агентов перед приёмкой.

**Не берёт:** объёмную реализацию по готовому детальному ТЗ (это Codex), первичное исследование незнакомой подсистемы (это Gemini), рутинное обслуживание (это OpenHands Agent).

**Обязательно:** каждое решение, затрагивающее более одного модуля, оформляется ADR в `docs/adr/`.

**Кто проверяет:** Codex (реализация, тесты, сборка) и/или Gemini (альтернативная архитектура). Claude не принимает собственную работу.

---

## Codex — `Codex-Quant-Implementation`

**Берёт:**

- реализацию чётко описанных функций, где scope и acceptance criteria однозначны;
- тестирование: новые тесты, покрытие торгового ядра (`Q-05`, `RM-P1-021`);
- исправление ошибок с известной причиной;
- build / typecheck / lint / прогон гейтов и приведение их к зелёному;
- **независимый code review изменений Claude** — по назначению Control Center.

**Не берёт:** выбор архитектуры (это Claude), задачи с формулировкой «разобраться» (это Gemini), изменение `TINKOFF_SANDBOX` и любых боевых параметров.

**Особенность:** при review изменений Claude Codex работает в **своём** worktree на том же base commit либо ревьюит PR — но не правит ветку Claude.

**Кто проверяет:** Claude (архитектурная корректность) или владелец.

---

## Gemini CLI — `Gemini-Quant-Research`

**Берёт:**

- исследование кодовой базы: где что лежит, как связано, где расхождения;
- поиск альтернативных решений там, где выбор неочевиден;
- задачи с большим контекстом: сквозное чтение крупных подсистем и документов;
- документацию;
- независимый review — UX, архитектурный или реализационный, по назначению Control Center.

**Режим по умолчанию — read-only.** Без явного scope на изменение файлов Gemini не правит код, не коммитит и не открывает PR: результат возвращается текстом в handoff. Свой worktree выдаётся всё равно — чтобы чтение шло по фиксированному base commit.

**Не берёт:** security-sensitive изменения, изменения торгового ядра, финальную интеграцию.

**Хорошие цели для исследования** (известные расхождения из Source Pack): `A-05` два Telegram-бота · `A-06` дубли модулей и контрактов · две схемы БД · два `rules.yaml` · `Q-02` дрейф дизайн-токенов · `Q-05` торговая логика без тестов.

---

## Встроенный OpenHands Agent — `OpenHands-Quant-Maintenance`

Настраивается **последним**, после того как работают Claude, Codex, Gemini, GitHub и worktree-поток. На 2026-08-06 — `OPTIONAL_NOT_CONFIGURED` (нет LLM credential).

**Берёт:**

- issue triage: разбор и маркировка задач на GitHub;
- обслуживание зависимостей — с учётом запрета `npm audit fix --force` (`S-03`);
- повторяемые автоматизации (Automations в Canvas);
- подготовку отчётов и сводок;
- небольшие изолированные задачи в одном файле.

**Не берёт:** ничего, что затрагивает торговый цикл, безопасность, схему БД, заявления на сайте.

## Матрица: кто исполняет, кто проверяет

| Тип задачи | Исполнитель | Независимая проверка |
|---|---|---|
| Архитектурное решение, ADR | claude | gemini (альтернатива) + владелец |
| Межмодульный рефакторинг | claude | codex (тесты, сборка) |
| Security: сессии, audit, шифрование | claude | codex (тесты) + владелец |
| Реализация по готовому ТЗ | codex | claude (архитектура) |
| Новые тесты, покрытие | codex | claude или gemini |
| Багфикс с известной причиной | codex | claude, если затронут более одного модуля |
| Приведение гейтов к зелёному | codex | claude |
| Исследование подсистемы | gemini | — (результат идёт в Control Center) |
| Поиск альтернатив решения | gemini | claude (оценка применимости) |
| Документация | gemini | claude (соответствие коду) |
| UX / архитектурный review | gemini | — |
| Issue triage, зависимости, отчёты | openhands | claude при затрагивании кода |
| Инфраструктура агентской среды | claude | codex (скрипты, проверки) |

## Правила выбора исполнителя

1. **Задача, где неочевидно «как» → gemini** (исследование), затем **claude** (решение), затем **codex** (реализация). Не поручать реализацию, пока «как» не определено.
2. **Задача, где очевидно «как» → сразу codex.** Привлекать Claude к рутинной реализации — потеря времени.
3. **Исполнитель и рецензент — всегда разные агенты.** Автор не проверяет себя.
4. **Один Task ID — один исполнитель.** Review оформляется отдельной задачей со своим ID, своей веткой и своим worktree.
5. **Задача, требующая credential или OAuth, не назначается агенту** — это OWNER CHECKPOINT (`OPERATING_MODEL.md`, уровень 0).
6. **Файл повышенного риска конфликта** (`docs/source/12 §5`) в один момент времени принадлежит одной задаче. Control Center проверяет это перед постановкой.
