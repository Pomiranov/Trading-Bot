# QuantFlow — Инструкция по загрузке знаний

Как правильно добавлять теорию, конспекты и книги в базу знаний бота.

---

## Структура папок

```
knowledge/
├── raw/                  ← сырые материалы КАК ЕСТЬ (архив, не трогается ботом)
│   ├── books/                книги (PDF, EPUB)
│   ├── courses/              конспекты, заметки, MD-файлы
│   └── scans/                фото/сканы рукописного
│
├── processed/            ← извлечённые знания в едином формате (бот читает это)
│   ├── technical/            теханализ: индикаторы, паттерны
│   ├── risk/                 риск-менеджмент + психология
│   ├── strategies/           торговые стратегии
│   └── market_theory/        теория рынка: макро, микроструктура
│
└── rules/                ← готовые IF-THEN правила
    └── rules.yaml            то что реально влияет на торговлю
```

---

## Поток обработки

```
1. Кидаешь файл в raw/
        ↓
2. Claude Code извлекает знания → processed/ (единый формат MD)
        ↓
3. Из processed/ выделяются конкретные правила → rules/rules.yaml
```

**Принцип:** сырьё → структура → исполняемые правила.

## Шаблон для стратегии

Файл: `processed/strategies/название.md`

```markdown
# Название стратегии

## Тип
Вход / Выход / Фильтр

## Рынки
stocks, futures, crypto (нужное оставить)

## Рыночный режим
trending / ranging / volatile — где работает

## Условия входа
- Условие 1 (конкретно, измеримо)
- Условие 2
- Условие 3

## Условия выхода
- Тейк-профит: сколько R или уровень
- Стоп-лосс: где ставить
- Трейлинг: если есть

## Риск
- Размер позиции: % от капитала
- Максимальный риск на сделку

## Источник
Книга/курс, глава/урок

## Заметки
Любые нюансы, исключения, предупреждения
```

## Шаблон для индикатора / паттерна

Файл: `processed/technical/название.md`

```markdown
# Название индикатора или паттерна

## Что это
Краткое определение в 1-2 предложения

## Как рассчитывается
Формула или описание расчёта

## Что показывает
Какой сигнал даёт

## Как использовать
- В каком режиме рынка работает
- С какими другими индикаторами сочетается
- Типичные ложные сигналы

## Параметры
- Период: обычное значение
- Пороги: например RSI > 70 = перекупленность

## Источник
Книга/курс, глава
```

## Правила именования файлов

- Только латиница, нижний регистр, подчёркивания
- Понятное имя: `breakout_strategy.md`, не `strat1.md`
- Один файл = одна концепция/стратегия/индикатор

Примеры:
```
processed/strategies/breakout_volume.md
processed/strategies/trend_pullback.md
processed/technical/rsi_divergence.md
processed/risk/position_sizing.md
processed/market_theory/order_flow.md
```

## Как добавлять — пошагово

1. Положи любой файл (PDF, Word, MD, фото) в нужную папку `raw/`
2. Скажи Claude Code:
   ```
   Обработай файл raw/books/название.pdf
   Извлеки знания и разложи по processed/ используя шаблоны
   из knowledge/HOW_TO_ADD_KNOWLEDGE.md
   ```
3. Claude Code прочитает файл, извлечёт суть, создаст структурированные MD
4. Проверь результат, поправь если нужно
5. Когда наберётся достаточно — попроси свести правила в rules.yaml

## Конвейер разбора книг по главам (chapter-reader)

Для больших книг вместо ручного «обработай файл» есть конвейер: субагент
`chapter-reader` читает по одной главе и пишет карточку, черновики правил и
конспект. Он ничего не внедряет — выход идёт на ревью человеку.

```bash
python tools/build_chapter_queue.py --detect-offset 20   # замерить page_offset
python tools/build_chapter_queue.py --page-offset -12    # черновик очереди
# сверить knowledge/queue/chapters.draft.yaml глазами → перенести pages
#           в knowledge/queue/chapters.yaml
python tools/read_chapters.py --dry-run                  # что будет сделано
python tools/read_chapters.py --only 4                   # одна глава
python tools/read_chapters.py --limit 3                  # батч
```

Что получается на главу: `knowledge/cards/chNN.md` (правила-кандидаты, фичи,
гипотезы, вопросы, чего в главе нет), `knowledge/rules/candidates/chNN_*.yaml`
и конспект в `processed/<категория>/`. По окончании батча — сводка в Telegram.

Правила агента (`.claude/agents/chapter-reader.md`): каждое правило со
ссылкой на страницу; любой численный параметр либо цитата из книги, либо
`REQUIRES_DECISION`; фичи выписываются всегда, даже для слабых правил;
неоднозначности не разрешаются, а идут в «Вопросы»; статус главы всегда
`read_pending_review`. Писать агент может только в `knowledge/cards/`,
`knowledge/rules/candidates/`, `knowledge/processed/` — остальное режет хук
`tools/guard_write_path.py`. Боевые `rules*.yaml` и статусы глав в
`schwager_index.md` меняет только человек.

Нужна рабочая авторизация `claude` в том же терминале: раннер делает
preflight-проверку и прерывается, если CLI не отвечает, чтобы не пометить
главы `failed` из-за среды.

## Важные принципы

**Не дублируй.** Одна стратегия — один файл. Если встретил её в двух книгах,
дополни существующий файл, а в источниках укажи оба.

**Будь конкретным.** "Покупать когда рынок растёт" — плохо. "Покупать когда
цена выше EMA200 и RSI между 40 и 60" — хорошо. Бот понимает только измеримое.

**Сохраняй источник.** Всегда указывай откуда знание — потом сможешь проверить
и углубить.

**Раздели факты и мнения.** Математика индикатора — факт. "Эта стратегия
лучшая" — мнение. Помечай мнения как мнения.

**raw/ — это архив.** Никогда не удаляй оттуда оригиналы. processed/ можно
переделывать, raw/ — неприкосновенный запас.
