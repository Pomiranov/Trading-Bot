## Почему утрачены — измерено, а не предположено

`HKLM\SYSTEM\CurrentControlSet\Control\CrashControl`:

```
CrashDumpEnabled : 7      (автоматический дамп памяти)
MinidumpDir      : C:\WINDOWS\Minidump
MinidumpsCount   : 5      ← кольцо на ПЯТЬ файлов
DumpFile         : C:\WINDOWS\MEMORY.DMP
Overwrite        : 1      ← полный дамп перезаписывается каждым падением
```

Два независимых механизма потери:

1. **кольцо на 5 файлов** — шестой вытесняет первый;
2. что-то вычистило и эти пять до трёх (Очистка диска / Контроль памяти —
   не проверялось, для сохранения улики неважно).

**`C:\WINDOWS\MEMORY.DMP` ОТСУТСТВУЕТ**, хотя событие 1001 от 02.08 16:18:26
прямо говорит «A dump was saved in: C:\WINDOWS\MEMORY.DMP». Полный дамп ядра за
наш случай уже потерян; выжил только минидамп.

## Срочность, названная числом

При `MinidumpsCount = 5` и текущих трёх файлах: **после двух следующих BSOD
начнёт вытесняться `072326`**, после пяти — будет утрачен и `080226`, то есть
наш. При наблюдаемом темпе (девять за июль, ~один раз в 3–4 дня) это **порядка
двух недель**.

## Что с ними делать дальше (НЕ сегодня)

Разбор — проверка гипотезы «виновный драйвер есть виртуальный сетевой адаптер
Docker Desktop» (см. PROJECT_STATE, раздел «Заведено 2026-08-02»). Инструмент —
WinDbg / `!analyze -v`, поле `IMAGE_NAME` / `MODULE_NAME`. Три дампа дают
проверку на воспроизводимость: один и тот же виновник в трёх независимых
падениях — это уже не совпадение.

Косвенный кандидат, зафиксированный до разбора: в журнале System 01.08 и 02.08
рядом с каждой загрузкой стоят по две записи
`VBoxNetLwf — The driver detected an internal driver error`
(01.08 11:35:42, 11:35:43, 14:31:38, 14:31:39; 02.08 16:18:02 дважды).
`VBoxNetLwf` — сетевой фильтр VirtualBox, не Docker. **Это НЕ вывод и не
опровержение гипотезы**, а лишь второй кандидат, который разбор обязан
рассмотреть наравне с первым.
