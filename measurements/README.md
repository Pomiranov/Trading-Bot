# measurements/ — долговременный архив артефактов измерений

Заведён 2026-07-30 при закрытии долгов №25 и №37.

**Зачем.** Гейт `bot/backtest/run_osc_oos_debug.py` пишет `osc_debug_<метка>.csv`
рядом с собой и **перезаписывает** файл при прогоне с той же меткой. Пока конвенция
измерения не менялась, это было безобидно: артефакт всегда можно пересчитать. После
правки движка — нельзя. CSV, воспроизводящий опубликованное число под СТАРОЙ
конвенцией, становится единственным свидетельством этого числа.

**Правила каталога.**

- `*.csv` в git **не отслеживаются** (`.gitignore`), этот README — отслеживается.
  Конвенция должна переезжать между машинами, данные — не обязаны.
- Имя файла самоописательное: `osc_debug_<метка>__run-<дата прогона>__last-session-<последняя закрытая сессия>.csv`.
  **Две даты в имени, потому что их три** и они не совпадают — см. ниже.
- Каждый архивный файл описывается строкой в таблице ниже. Файл без строки — мусор:
  через полгода по нему нельзя сказать, что он воспроизводит.

**Три даты одного бара — почему обе стоят в имени.**

| понятие | пример | где встречается |
|---|---|---|
| дата прогона | 2026-07-28 | шапка `window_note`, строка `Прогон:` |
| последняя ЗАКРЫТАЯ сессия в данных | 2026-07-27 | шапка, `Последняя ЗАКРЫТАЯ сессия` |
| внутренняя метка того же бара | 2026-07-26 21:00+00 | колонки `entry`/`exit` в CSV |

Все три уже путались в документах проекта: PROJECT_STATE помечает `+74 054.52` как
«данные по сессию 28.07» (это **дата прогона**, последняя сессия там 27.07), а
`+77 851.57` — «по сессию 29.07» (а вот тут это действительно **последняя сессия**).
Одно слово, два смысла. Установлено замером 30.07: прогон с `--as-of 2026-07-27`
воспроизводит первое число побайтово, с `--as-of 2026-07-29` — второе.

**Как воспроизвести любой архивный файл.**

```
python bot/backtest/run_osc_oos_debug.py \
    --label <метка> --show-oos \
    --as-of <последняя закрытая сессия из имени файла> \
    [--rules <файл правил, если не дефолтный>]
```

`--as-of` — это МОСКОВСКАЯ ТОРГОВАЯ СЕССИЯ включительно, не метка бара.

**Оба файла содержат ФАНТОМНУЮ сделку** — позицию SBER, открытую на краю данных и
принудительно закрытую по последнему бару (долг №25). В `off` это строка 178 файла
(сделка 177 без заголовка): `D1,SBER,2026-07-23 21:00,2026-07-26 21:00,21117.22,WIN`.
Помечена `WIN` наравне с закрытыми по правилу — отличить её в артефакте нечем, и
именно поэтому файлы сохранены до правки конвенции.
